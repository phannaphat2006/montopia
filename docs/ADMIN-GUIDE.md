# คู่มือใช้งานระบบหลังบ้าน MONSTOPIA

เอกสารนี้อธิบายการใช้งานสำหรับผู้เริ่มต้น โดยไม่จำเป็นต้องแก้โค้ดเว็บไซต์

## 1. เปิดระบบบนเครื่อง

วิธีง่ายที่สุดสำหรับเครื่องนี้: ดับเบิลคลิกไฟล์ `Start-MONSTOPIA.cmd` ในโฟลเดอร์โครงการ โปรแกรมจะตรวจและเปิด MySQL ก่อน ตรวจการเชื่อมต่อฐานข้อมูล แล้วเปิด Laravel ที่พอร์ต 8000 หากยังไม่ทำงาน โดยไม่สร้างบัญชีใหม่ ไม่แก้ข้อมูล และไม่รัน Migration เพิ่ม

เมื่อขึ้นข้อความ `MONSTOPIA is running on this computer` ให้เปิดลิงก์ Workspace ที่แสดง หากเปิดเครื่องใหม่ให้ดับเบิลคลิกไฟล์นี้อีกครั้ง ลิงก์ `127.0.0.1` ใช้ได้เฉพาะเครื่องตัวเอง ยังไม่ใช่ลิงก์สำหรับส่งให้เพื่อน

ไฟล์เปิดระบบนี้ใช้ชุด PHP/MySQL ที่อยู่ใน `.runtime` ของเครื่องพัฒนา ซึ่งไม่รวมอยู่บน GitHub หากย้ายเครื่องต้องติดตั้ง Runtime และตั้งค่า `.env` ก่อน

เปิด PowerShell ที่โฟลเดอร์โครงการแล้วใช้คำสั่ง:

```powershell
D:\motopia\.runtime\php\php.exe artisan serve
```

จากนั้นเปิด:

- เว็บไซต์บริษัท: `http://127.0.0.1:8000`
- ระบบหลังบ้าน: `http://127.0.0.1:8000/workspace`

หน้าต่าง PowerShell ต้องเปิดค้างไว้ระหว่างใช้งาน ถ้าปิดหน้าต่าง เว็บบนเครื่องจะหยุดทำงาน

## 2. สร้างบัญชีผู้ดูแลครั้งแรก

ถ้ายังไม่มีบัญชี ให้หยุดเซิร์ฟเวอร์ด้วย `Ctrl+C` แล้วใช้คำสั่ง:

```powershell
D:\motopia\.runtime\php\php.exe artisan monstopia:create-admin admin@example.com --name="ชื่อผู้ดูแล" --generate
```

ระบบจะแสดงรหัสผ่านชั่วคราวหนึ่งครั้ง ให้เก็บไว้ในที่ปลอดภัยแล้วเข้าสู่ระบบที่ `/workspace` ระบบจะบังคับเปลี่ยนรหัสผ่านก่อนเปิดเมนูอื่น รหัสผ่านใหม่ต้องยาวอย่างน้อย 12 ตัว มีตัวพิมพ์เล็ก ตัวพิมพ์ใหญ่ และตัวเลข

## 3. ความหมายของ CRUD

- Create: กดปุ่ม “เพิ่ม” หรือ “เขียนบทความ” เพื่อสร้างข้อมูล
- Read: เปิดแต่ละเมนูเพื่อดูข้อมูลที่บันทึกไว้
- Update: กด “แก้ไข” แล้วบันทึกข้อมูลใหม่
- Delete: กด “ลบ” และยืนยันก่อนนำข้อมูลออก

## 4. เมนูที่ใช้บ่อย

- ภาพรวม: ดูจำนวนบรีฟ โครงการ บัญชีลูกค้า งานที่กำลังเดิน และข้อมูลเว็บไซต์
- ข้อมูลบริษัท: แก้ชื่อ คำแนะนำ อีเมล ที่อยู่ และเลขทะเบียน
- บริการ: จัดการรายการบริการ โดย `Slug` ใช้ตัวอักษรอังกฤษ ตัวเลข และเครื่องหมายขีดกลาง เช่น `web-application`
- แพ็กเกจ: กำหนดราคา ระยะเวลา สิ่งที่ได้รับ และเลือกแพ็กเกจแนะนำ
- ผลงาน: เพิ่มภาพหน้าจอจริง ชื่อโครงการ รายละเอียด และเทคโนโลยี
- ข่าวสาร: บันทึกเป็นฉบับร่างก่อน แล้วเปลี่ยนสถานะเป็นเผยแพร่เมื่อพร้อม
- บรีฟลูกค้า: อ่านรายละเอียด ตอบกลับทางอีเมล สร้างบัญชี Client และเปลี่ยนบรีฟเป็น Project
- โครงการ: กำหนดสถานะ เปอร์เซ็นต์ วันเริ่ม/วันส่ง เพิ่ม Milestone แนบไฟล์ และบันทึกประวัติ
- ผู้ใช้งาน: Administrator สร้าง แก้ไข และลบบัญชีตามบทบาท ทุกบัญชีใหม่ต้องเปลี่ยนรหัสผ่านครั้งแรก

## 5. เส้นทางรับงานที่ควรทำตาม

1. ลูกค้าส่งแบบฟอร์มที่ `/brief` ข้อมูลจะบันทึกในตาราง `inquiries`
2. Admin เปิดเมนู “บรีฟลูกค้า” อ่านความต้องการและตอบกลับ ข้อความจะถูกบันทึกก่อนส่งอีเมล
3. Admin/Staff กด “รับงานและเปิดโครงการ” แล้วยืนยัน หรือเลือกสถานะรับงานในหน้าตอบกลับ โครงการจะถูกสร้างอัตโนมัติและหน้าเว็บเปลี่ยนไปเมนูโครงการ ไม่ต้องสร้างซ้ำ การรับงานซ้ำจะใช้โครงการเดิม ไม่รีเซ็ตข้อมูล
4. ระบบใช้ชื่อและรายละเอียดจากบรีฟ เริ่มสถานะรอเริ่ม ความคืบหน้า 0% วันเริ่มตั้งต้นเป็นวันที่เปิดโครงการ มูลค่า 0 เป็นค่ารอระบุ และเว้นวันส่งไว้ ให้กด “แก้ไขข้อมูล” เพื่อกำหนดราคาที่ตกลงและวันที่จริง ถ้ามีบัญชี Client อีเมลตรงกันระบบผูกให้อัตโนมัติ ถ้ายังไม่มีจะเปิดโครงการแบบไม่ผูกบัญชีก่อน โดยลูกค้าจะยังเปิดดูไม่ได้ Admin ต้องสร้างบัญชี Client ส่งรหัสผ่านชั่วคราวทางช่องทางส่วนตัว แล้วเลือกบัญชีในข้อมูลโครงการ ระบบไม่สร้างบัญชีหรือรหัสผ่านจากอีเมลในบรีฟเอง
5. Admin เพิ่ม Milestone และบันทึกความคืบหน้า โดยเลือกได้ว่าจะให้ลูกค้าเห็น/รับอีเมลหรือเก็บเป็นบันทึกภายใน
6. ลูกค้า Login ที่ `/workspace` และเห็นเฉพาะโครงการ ไฟล์ และประวัติที่ผูกกับบัญชีของตน

สำหรับบรีฟเก่าที่สถานะรับงานแล้วแต่ยังไม่มีโครงการ ใช้ `php artisan monstopia:sync-accepted-inquiries --dry-run` เพื่อตรวจจำนวน และ `php artisan monstopia:sync-accepted-inquiries` เพื่อสร้างโครงการที่ขาด คำสั่งไม่เปลี่ยนโครงการเดิม ไม่ส่งอีเมล และเรียกซ้ำได้โดยไม่สร้างโครงการซ้ำ

## 6. ความหมายของสถานะโครงการ

- รอเริ่ม (`planned`): ตกลงรับงานแล้วแต่ยังไม่เริ่มพัฒนา
- กำลังทำ (`in_progress`): ทีมกำลังดำเนินงาน
- รอตรวจ (`review`): ส่งให้ลูกค้าหรือทีมทดสอบตรวจ
- เสร็จแล้ว (`completed`): ส่งมอบครบ ระบบตั้งความคืบหน้าเป็น 100%
- เก็บถาวร (`archived`): ปิดการใช้งานแต่เก็บประวัติไว้ ไม่ลบข้อมูลจริง

## 7. ไฟล์และประวัติการอัปเดต

รองรับ PDF, JPG, PNG, DOCX, XLSX และ ZIP ขนาดไม่เกิน 10 MB ไฟล์เก็บในพื้นที่ Private และดาวน์โหลดได้เฉพาะ Admin/Staff หรือ Client เจ้าของโครงการ การอัปเดตทุกครั้งเก็บชื่อผู้บันทึก เวลา หัวข้อ รายละเอียด และเปอร์เซ็นต์ เพื่อใช้ตรวจสอบย้อนหลัง

## 8. การเผยแพร่ข้อมูล

ข้อมูลที่ตั้งค่าเป็น “เผยแพร่” จะปรากฏบนหน้าเว็บไซต์หลังบันทึกและโหลดหน้าใหม่ ข้อมูลที่ตั้งค่าเป็น “ซ่อน” หรือบทความสถานะ “ฉบับร่าง” จะเห็นเฉพาะในระบบหลังบ้าน

## 9. สำรองข้อมูล

ทดสอบสำรองด้วยคำสั่ง:

```powershell
D:\motopia\.runtime\php\php.exe artisan monstopia:backup-all
```

ชุดสำรอง SQL + ไฟล์แนบ + manifest อยู่ใน `storage/app/private/backups` และไม่ถูก Commit ขึ้น Git งาน Production ต้องตั้ง Cron ให้ `php artisan schedule:run` ทำงานทุกนาที เพื่อเรียก Backup เวลา 02:00 ตามเวลาไทย ใน Windows มีตัวติดตั้ง Scheduled Task สำหรับเครื่องนี้ การเปิดหน้าเว็บอย่างเดียวไม่ทำให้ Backup ทำงาน ชุดเก่าไม่ถูกลบอัตโนมัติ และควรมีสำรองแยกอุปกรณ์ด้วย ดู `docs/BACKUP-GUIDE.md`

## 10. ก่อนใช้งานจริงบนอินเทอร์เน็ต

ต้องใช้โฮสต์ที่รองรับ PHP/Laravel และ MySQL ตั้งค่า HTTPS, `APP_DEBUG=false`, อีเมล และ LINE Messaging API ห้ามนำไฟล์ `.env` รหัสผ่าน หรือไฟล์ Backup ขึ้นพื้นที่สาธารณะ อ่านขั้นตอนเต็มที่ `docs/DEPLOYMENT.md`
