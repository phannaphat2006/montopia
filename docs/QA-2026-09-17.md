# รายงานตรวจ MONSTOPIA — 17 กันยายน 2569

## ขอบเขต

ตรวจในเครื่องพัฒนา Laravel + MySQL ตามรายการ 1, 4, 5 และ 6 ไม่ใช่การรับรอง Production และไม่เปิด Deploy, Firebase, SMTP หรือ LINE ในรอบนี้ ใช้บัญชีและข้อมูล QA แยกจากข้อมูลเดิม อีเมลใช้ array mailer จึงไม่มีการส่งข้อความจริงออกไปหาลูกค้า

## 1. วงจรรับงานและสิทธิ์

ผ่านการกรอกบรีฟหลายขั้นที่หน้าเว็บ บันทึกลง MySQL และเห็นรายการในหลังบ้าน จากนั้น Admin กดรับงานผ่านกล่องยืนยันในหน้าเว็บ โครงการถูกสร้างอัตโนมัติและผูกกับบัญชี Client ที่อีเมลตรงกัน ทดสอบแก้ชื่อ งบประมาณ วันเริ่ม/วันส่ง เพิ่ม Milestone และอัปเดตความคืบหน้าเป็น 40% สถานะรอตรวจ

Client เจ้าของงานเข้าสู่ระบบและเห็นโครงการ Milestone ความคืบหน้าและไฟล์สำหรับลูกค้า บัญชี Client อื่นเห็นรายการว่างและขอไฟล์โครงการนี้ไม่ได้ (403) ไฟล์ภายในทีมถูกซ่อนและดาวน์โหลดโดยลูกค้าไม่ได้ (403)

อัปโหลดรูปจริงผ่าน HTTP multipart API ได้ 201 ดาวน์โหลดโดยเจ้าของได้ 200 และ SHA-256 ของไฟล์ตรงกับต้นฉบับ ทดสอบปฏิเสธชนิดไฟล์ไม่อนุญาตและไฟล์เกิน 10 MB ในชุดทดสอบอัตโนมัติ

**ข้อจำกัด:** เครื่องมือควบคุมเบราว์เซอร์ไม่สามารถใส่ไฟล์ลงตัวเลือกไฟล์ของระบบปฏิบัติการได้ จึงยังไม่ยืนยันการเลือกและส่งไฟล์ผ่านปุ่มบนหน้าจอในรอบนี้ ไม่ได้ถือว่า API ผ่านเท่ากับ UI ผ่าน ต้องทดลองเลือกไฟล์และกดอัปโหลดด้วยมืออีกครั้ง

## 4. การกู้คืนฐานข้อมูล

สำรองเป็น SQL gzip และกู้คืนเข้า MySQL ทดสอบแยกที่พอร์ต 3307 ไม่เขียนทับฐานข้อมูลต้นทาง ทั้งสองระบบเป็น MySQL 8.4.11 เปรียบเทียบทุกแถวและ SHOW CREATE TABLE ของทั้ง 13 ตาราง รวมตาราง migrations ผ่านทั้งหมด การเปรียบเทียบโครงสร้างปรับเฉพาะรูปแบบ CHARACTER SET ที่ซ้ำซ้อน โดยยังตรวจ charset, collation, indexes และ constraints

- ฐานข้อมูลทดสอบ: `monstopia_restore_qa_20260916_204739`
- SHA-256 ของไฟล์สำรอง: `6909bd66f3c0f11a281f2b117d5aced301fab7c81f62a22a0c53a17ee8fc1d4f`
- จำนวนแถวขณะตรวจ: articles 3, company_profiles 1, inquiries 4, inquiry_replies 2, migrations 5, milestones 5, portfolios 1, project_attachments 3, project_updates 9, projects 3, service_packages 3, services 4, users 8

ปิด MySQL ทดสอบหลังเปรียบเทียบ ฐานข้อมูลและบัญชี QA ที่สร้างในต้นทางถูกล้างเฉพาะของรอบนี้หลังทดสอบ ข้อมูลเดิมไม่ถูกแก้ไข ไฟล์ SQL ไม่รวมเนื้อหาไฟล์แนบ ต้องสำรอง private storage แยกด้วย และต้องตั้ง Scheduler จริงบน Hosting เพื่อให้สำรองอัตโนมัติทำงาน

หลังล้างข้อมูล QA สำรองข้อมูลต้นทางอีกครั้งเป็น `monstopia_2026-09-16_20-48-48.sql.gz` และสำรองโฟลเดอร์ไฟล์แนบเดิมเป็น `project-files_2026-09-17_QA.zip` ใน private backup storage ไม่เผยแพร่บน GitHub ตัวสำรองใช้ Laravel fallback เพราะ mysqldump ของเครื่องเชื่อมต่อไม่ได้ การกู้คืน fallback ที่ทดสอบก่อนล้าง QA ผ่านแล้ว ส่วน ZIP ไฟล์แนบยังไม่ได้ทดสอบกู้คืนในรอบนี้

## 5. หน้าเว็บ มือถือ และเอกสาร

ตรวจหน้าแรกที่ 320, 390 และ 768 พิกเซล หน้า brief ที่ 320/390 หน้า operations ที่ 320 และเมนูหลังบ้านทุกหมวดที่ 320 รวมถึง Client Workspace และหน้ารายละเอียดที่ 390 ไม่พบการล้นแนวนอนในหน้าที่ตรวจ ตรวจแท็บบริการ FAQ บทความ และสถานะไม่มีโครงการ ใช้งานได้ ไม่ได้หมายถึงทดสอบทุกอุปกรณ์หรือทุกปุ่ม CRUD ด้วยมือ

แก้ ER Diagram ให้เส้นความสัมพันธ์ตรงกับตาราง ปรับ Data Dictionary และ PDF บท 3.7/3.9 ให้ตรงกับพฤติกรรมจริง ใช้ภาพเว็บที่ถ่ายจากส่วนติดต่อจริง ภาพประกอบที่ถ่ายไว้ก่อนหน้าอาจมีค่าตัวอย่างต่างจากกรณี QA รอบนี้ ไม่ใช้ภาพหน้าต่างเครื่องมือที่วาดจำลองเป็นหลักฐานการทดสอบ

แก้ประเด็นที่พบระหว่างตรวจ:

- เปลี่ยน native confirm เป็นกล่องยืนยันในหน้าเว็บ พร้อมปุ่มยกเลิก/ยืนยัน
- วันเริ่มโครงการอัตโนมัติใช้วันที่ประเทศไทย ไม่คลาดหนึ่งวันจาก UTC; เวลาสำรองรายวันเป็น Asia/Bangkok
- ลูกค้าดาวน์โหลดไฟล์ของโครงการเก็บถาวรไม่ได้ แม้มีลิงก์เก่า
- เอาคำกล่าวอ้าง HTTPS ออกจากฟอร์มที่ใช้ทดสอบ HTTP ในเครื่อง
- คู่มือใช้ตัวแปร `BACKUP_RETENTION_DAYS` ตรงกับระบบ

## 6. เวอร์ชันและ GitHub

บันทึกโค้ด คู่มือ ER Diagram และ PDF ใน commit เดียวกัน แล้วตรวจ remote main หลัง push GitHub เพื่อยืนยันว่าเป็นเวอร์ชันเดียวกับเครื่อง ไฟล์ `.env`, ข้อมูลฐานข้อมูล, ไฟล์ลูกค้าส่วนตัว, ข้อมูลรับรองและบัญชี QA ไม่อยู่ใน commit

## ยังไม่ครอบคลุม / ต้องทำก่อนใช้จริง

1. ทดลองอัปโหลดจากปุ่มเลือกไฟล์ด้วยมือ
2. ตั้งค่าและทดสอบ Firebase หากยังต้องการใช้งาน
3. ตั้ง SMTP และตรวจส่งอีเมลจริง (รอบนี้ยืนยันเฉพาะกระบวนการในระบบ)
4. เตรียม Hosting, HTTPS, APP_DEBUG=false, Scheduler และแผนสำรองทั้ง MySQL/ไฟล์แนบ
5. ทดสอบรอบ Production หลัง Deploy ซึ่งผู้ใช้กำหนดให้เป็นขั้นตอนสุดท้าย
