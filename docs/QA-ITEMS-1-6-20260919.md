## ปัญหาที่เจอจากการกดใช้จริง

หลัง Login Laravel เปลี่ยน Session และ CSRF token แต่ JavaScript เดิมจำ token เก่าไว้ จึงกดรับงานแล้วเจอ `CSRF token mismatch` แก้ให้ล้าง token ที่จำหลัง Login และหลังเปลี่ยนรหัสผ่าน เพื่อขอ token ใหม่สำหรับการบันทึกครั้งถัดไป หากหมดอายุ (HTTP 419) จะแจ้งภาษาไทยและให้ผู้ใช้ลองอีกครั้ง **ไม่ปิด CSRF และไม่ส่ง POST ซ้ำเอง**

เมื่อ Logout ล้างเนื้อหา Dialog และข้อความแจ้งเตือนด้วย เพื่อไม่ทิ้งข้อมูลของบัญชีก่อนหน้าไว้ใน DOM ที่ซ่อนอยู่เมื่อสลับบัญชีบนเครื่องเดียวกัน

ทดสอบซ้ำจาก Login แล้วรับบรีฟ QA สำเร็จ โครงการเปิดอัตโนมัติ ผูกบัญชี Client ตามอีเมลที่มีบทบาท Client บันทึกความคืบหน้า 25% แล้ว Client เห็นใน Workspace

ตรวจจอ 320 พิกเซลพบข้อความอีเมลในสรุปโครงการดันกรอบ Dialog จึงปรับ flex-wrap, min-width และ overflow-wrap; หลังแก้ความกว้างที่เลื่อนได้ใน Dialog เท่าความกว้างภายใน (254/254 px) ไม่ล้นแนวนอน จอหลักก็ไม่ล้น ไม่ใช่การรับรองการทดสอบบนโทรศัพท์จริงทุกยี่ห้อ

ช่วง QA ตั้ง mail เป็น array เฉพาะโปรเซสเว็บทดสอบ ไม่ส่งข้อความไปอีเมล fixture; หลังทดสอบปิดเฉพาะ PHP QA server ที่ระบุตัวแล้ว เปิดใหม่โดยใช้ SMTP ตาม `.env` ไม่เปลี่ยน credentials เจ้าของ

## อธิบายว่าแต่ละส่วนทำไปทำไม

### HTML: โครงสร้างและตำแหน่ง

`public/portal.html` เป็นโครงหน้าหลังบ้าน มีพื้นที่ `#workspace` สำหรับข้อมูล, Dialog สำหรับฟอร์ม และ `#notice` สำหรับผลการทำงาน รอบนี้เชื่อม stylesheet ใหม่เข้ากับ HTML เพื่อให้หน้ารู้จักกฎการจัดวางที่เพิ่ม ไม่ต้องสร้างหน้า HTML แยกสำหรับบรีฟแต่ละหน้า

### CSS: จัดให้อ่านและใช้ได้

HTML บอกว่ามีอะไร ส่วน `public/portal-workflow.css` บอกว่าแสดงอย่างไร จัดแถบเปลี่ยนหน้าด้วย Flexbox ให้เรียงและขึ้นบรรทัดใหม่บนจอเล็ก วางสถานะอีเมลในคอลัมน์เนื้อหาของประวัติ ไม่หล่นไปคอลัมน์จุด Timeline ที่แคบ ใช้ overflow-wrap ให้ข้อความอีเมลยาวตัดบรรทัดได้ ไม่ใช่แค่ซ่อนส่วนที่ล้น

### JavaScript: ให้ปุ่มคุยกับ Laravel

`public/portal.js` ใช้ `fetch()` เรียก API พร้อม Session cookie และ CSRF token เช่น `/api/admin/inquiries?page=2` เมื่อได้รับ JSON จึงสร้างรายการใหม่ อ่าน metadata จาก Laravel เพื่อแสดงจำนวนหน้า ไม่เดาจำนวนหน้าเอง แสดง Loading ระหว่างรอ; Disable ปุ่มขณะส่ง; แสดงคำอธิบายเมื่อผิดพลาด

การเลือกไฟล์ใช้ FormData ไม่แปลง binary เป็น JSON และไม่ตั้ง Content-Type เอง เพื่อให้ Browser ใส่ multipart boundary ที่ถูกต้อง หากแค่เก็บชื่อไฟล์ใน SQL จะยังดาวน์โหลดไม่ได้ ต้องบันทึกเนื้อหาไฟล์ใน private Storage ด้วย

### PHP/Laravel: ตรวจข้อมูลและสิทธิ์

Controller รับ request ตรวจข้อมูล แล้วอ่าน/เขียนผ่าน Model กับ MySQL JavaScript ซ่อนปุ่มไม่ใช่การป้องกันสิทธิ์ เพราะใครอาจเรียก API เองได้ Laravel จึงต้องตรวจผู้ใช้และความเป็นเจ้าของโครงการทุกครั้ง แม้รู้ลิงก์ดาวน์โหลดก็เปิดไฟล์ของคนอื่นไม่ได้

สถานะอีเมลบันทึกใน `project_updates` ผ่าน migration ใหม่ การเพิ่มคอลัมน์ใช้ migration เพื่อให้เครื่องอื่นติดตั้งโครงสร้างเดียวกัน ไม่แก้ตารางด้วยมือทีละเครื่อง ความคืบหน้ายังบันทึกอยู่แม้ SMTP ส่งไม่สำเร็จ จึงไม่สูญเสียงานเพียงเพราะระบบอีเมลมีปัญหา

การลองส่งใหม่จองรายการด้วย conditional database update ก่อนส่ง ป้องกันสองคำขอส่งพร้อมกัน รายการที่ส่งแล้ว/กำลังส่งไม่ให้กดส่งซ้ำ แต่ SMTP ไม่ใช่ระบบ exactly-once ถ้าโปรเซสหยุดกลางทางต้องตรวจปลายทางก่อน รายการข้อมูลเดิมหรือ composite mailer ที่ยืนยันช่องทางไม่ได้แสดง unknown และไม่ให้ส่งซ้ำโดยเดาเอง

### สำรอง: ต้องเก็บทั้งข้อมูลและไฟล์

MySQL เก็บแถวข้อมูล เช่นชื่อโครงการและที่อยู่ไฟล์ ส่วน Storage เก็บเนื้อหาเอกสาร สำรอง SQL อย่างเดียวเหมือนเก็บสารบัญโดยไม่มีหนังสือ คำสั่ง `monstopia:backup-all` จึงเก็บสองส่วนพร้อม manifest; SHA-256 เหมือนลายนิ้วมือสำหรับเทียบไฟล์ ไม่ใช่การเข้ารหัสและไม่ป้องกันผู้ที่อ่านไฟล์ได้

มีคำสั่งสำรองในโค้ดอย่างเดียวไม่ทำให้รันทุกคืน จึงเพิ่ม Windows Task Scheduler ให้เรียก runner ในเวลาที่ตั้งไว้; สำหรับ Hosting/VPS ในอนาคตใช้ cron/Laravel Scheduler แทน ไม่ใช่ใช้ PHP development server เป็น Production

## วิธีเปิดและลองด้วยตัวเอง

เปิด PowerShell ที่ `D:\motopia` แล้วพิมพ์:

```powershell
.\Start-MONSTOPIA.ps1
```

เปิด `http://127.0.0.1:8000` หรือ `/workspace` บัญชีจริงยังใช้บัญชีเดิม ไม่มีการเปลี่ยนรหัสผ่านในรอบนี้ ลิงก์ 127.0.0.1 ใช้ได้เฉพาะคอมพิวเตอร์นี้ **ส่งให้เพื่อนผ่าน LINE ยังเข้าไม่ได้** จนกว่าจะ Deploy

ทดสอบงานโดยใช้ข้อมูลตัวอย่างไม่ใช่ลูกค้าจริง: ส่งบรีฟ → เปิดหลังบ้านดูบรีฟ → รับงานและเปิดโครงการ → ตรวจบัญชี Client ที่ผูก → ระบุวัน/งบ/เพิ่ม Milestone → บันทึกความคืบหน้าและแนบไฟล์ → เข้า Client ดูรายละเอียด หากใช้ SMTP จริง ขั้นตอนแจ้งลูกค้าอาจส่งอีเมลจริง ต้องใช้ผู้รับที่ได้รับอนุญาต

ก่อนงานบริษัทจริงยังต้อง Deploy PHP+MySQL, HTTPS, APP_DEBUG=false, จำกัดการเข้าถึงฐานข้อมูล (ห้ามเปิดพอร์ต MySQL ให้สาธารณะ), credentials/สิทธิ์ไฟล์, offsite+encrypted backup, monitoring และทดลองกู้คืน Login/API ครบระบบบนสภาพแวดล้อมใหม่ การกู้คืนที่ทำรอบนี้ตรวจตาราง/โครงสร้าง/ไฟล์ตรง manifest ไม่ใช่การเปิดเว็บ Production จากเครื่องกู้คืน
