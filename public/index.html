การทำงานเริ่มจากขอบเขตที่ชัดเจน ตั้งแต่สิ่งที่ระบบต้องทำ ผู้ที่จะใช้งาน ไปจนถึงวิธีทดสอบและแนวทางดูแลหลังส่งมอบ

COMMON QUESTIONS

ก่อนเริ่มโครงการ
ควรรู้อะไรบ้าง

ยังไม่มี Requirement ชัดเจน เริ่มคุยได้ไหม?

เริ่มได้จากปัญหาที่พบและตัวอย่างการทำงานเดิม เช่น แบบฟอร์ม รายงาน หรือขั้นตอนที่ใช้เวลา ข้อมูลเหล่านี้ช่วยให้กำหนดความต้องการระยะแรกได้

ประเมินค่าใช้จ่ายจากอะไร?

พิจารณาฟังก์ชัน จำนวนบทบาทผู้ใช้งาน การเชื่อมต่อระบบ ข้อมูลที่ต้องย้าย และการดูแลหลังส่งมอบ ค่าใช้จ่ายภายนอก เช่น คลาวด์หรือบริการ API ควรแยกให้เห็นในข้อเสนอ

สามารถต่อยอดระบบเดิมได้หรือไม่?

ต้องตรวจสอบเทคโนโลยี เอกสาร สิทธิ์การเข้าถึง และข้อจำกัดของระบบเดิมก่อน เพื่อประเมินว่าควรเชื่อมต่อ ปรับปรุง หรือพัฒนาบางส่วนใหม่

ได้ Source code และการดูแลหลังส่งมอบอย่างไร?

สิทธิ์ใน Source code เอกสาร ระยะรับประกัน และบริการดูแลควรระบุไว้ในสัญญาของแต่ละโครงการ รวมถึงข้อจำกัดของซอฟต์แวร์หรือบริการจากบุคคลที่สาม
